deptty was ported to dtk-rs d7a55c6 (scoped runtime + ownership tracking). Hard rules the new dtk enforces, and how deptty complies:

- `DApplication::new` is gone; use `DApplication::with(name, |app| { ... app.exec() })` — the token cannot escape the closure. QApplication must be built on the process main thread, so the integration test uses `harness = false` in Cargo.toml (libtest runs tests on worker threads).
- Widget constructors return `Owned<T>`; dropping the guard of a never-parented QObject queues `delete_later`. deptty `std::mem::forget`s the win/tabbar/root guards in `boot()` (scoped runtime cleanup registry destroys them at scope exit); parented widgets (panes, scrollbars, containers, per-pane QTimer/QSocketNotifier parented to the pane) drop their guards freely.
- Handles (QWidget/PaintWidget/DTabBar/...) are `Clone` but not `Copy`; clones share an `Rc<ObjectGuard>`; calling a method on a destroyed object panics.
- `delete_later()` panics for parented widgets (`guard_can_delete` = authority && !was_parented && no Qt parent; QTimer/QSocketNotifier exempt). deptty hides dead panes/containers instead of deleting; Qt parent chain owns them until exit.
- Paint callbacks borrow native state: ANY QObject call inside a PaintWidget Paint handler panics ("Qt native state is borrowed"), incl. `QTimer::single_shot` and palette queries. deptty keeps scrollbar/IME sync in `sync_chrome()`, called from the repaint timer and Resize arm; divider color channels are resolved once at boot.
- `NativeCall::drop` drains deferred signal callbacks: any dtk native call can synchronously run an unrelated queued callback (e.g. a menu action). Never hold the `tabs` RefCell borrow across any dtk call — collect handles under the borrow, drop it, then call. Layout is split: `collect_layout` (pure) + `relayout_tab` (applies borrow-free).
- Panics in callbacks are swallowed at the FFI boundary (printed, loop continues), so a panicking handler looks like a hang/flood, not a crash. Debug with RUST_BACKTRACE=1 — the outstanding RefCell borrow is always an ancestor frame in the panic backtrace.
